Step 1 — Configure Email Sending (SMTP)

To send emails, the portal needs access to an SMTP server. The easiest option for most home labs is Gmail with an App Password — no extra servers needed.

💡 If you haven't done this yet, open the Setup Wizard and complete Step 4 (Email). You can also update environment variables manually.

Choose your email provider:

Gmail
smtp.gmail.com · Port 587
Outlook / Hotmail
smtp.office365.com · Port 587
Custom / Self-hosted
Your own SMTP server
1

Create a Gmail App Password

Google requires an App Password for third-party email clients — it's a 16-character password separate from your normal Google password.

  • Go to myaccount.google.com → Security
  • Make sure 2-Step Verification is enabled (required)
  • Go to App Passwords (search for it in the Security page)
  • Select app: Mail, device: Other, name it Plex Portal
  • Copy the 16-character password shown (you won't see it again)
💡 The App Password looks like: abcd efgh ijkl mnop — paste it without spaces.
2

Enter these settings in the Setup Wizard

SMTP_HOST = smtp.gmail.com SMTP_PORT = 587 SMTP_USERNAME = yourname@gmail.com SMTP_PASSWORD = abcdefghijklmnop ← App Password SMTP_FROM_NAME = {{ site_name }} SMTP_FROM_EMAIL = yourname@gmail.com
3

Test the connection

After saving, go to the Admin Panel and click Send Test — enter your own email and make sure you receive it.

1

Enable SMTP AUTH in Outlook

Microsoft disabled SMTP AUTH on some tenants. Make sure it's enabled:

  • Go to admin.microsoft.com → Users → Active Users
  • Click the account → Mail tab → Manage email apps
  • Check Authenticated SMTP and save
2

Settings

SMTP_HOST = smtp.office365.com SMTP_PORT = 587 SMTP_USERNAME = yourname@outlook.com SMTP_PASSWORD = your-password
For personal Outlook accounts (hotmail.com, live.com, outlook.com), the same settings apply. You may need to enable Less Secure App Access or create an App Password under Security → Advanced security options.
1

Gather your SMTP credentials

You'll need the following from your email provider or self-hosted mail server:

  • Hostname — e.g. mail.yourdomain.com
  • Port — typically 587 (STARTTLS) or 465 (SSL)
  • Username — usually your full email address
  • Password — your email password or app password
2

Set environment variables

SMTP_HOST = mail.yourdomain.com SMTP_PORT = 587 SMTP_USERNAME = notifications@yourdomain.com SMTP_PASSWORD = your-password SMTP_FROM_NAME = {{ site_name }} SMTP_FROM_EMAIL = notifications@yourdomain.com
📌 If you're using port 465 (SSL/TLS instead of STARTTLS), set SMTP_TLS=false — the code will then attempt a direct SSL connection.

How the matching works

When Overseerr fires a Media Available webhook, the portal looks for a subscriber whose:

  • Email matches the Overseerr account email that made the request, OR
  • Plex username matches the Overseerr username that made the request

This is why subscribers should fill in their Plex username during sign-up — it ensures the match works even if email addresses differ between Overseerr and the portal subscription.

Step 3 — Plex's Built-in Newsletter (Optional)

Plex Media Server has its own built-in newsletter feature that automatically emails your Plex home users about recently added content. This is separate from the portal's newsletter system — you can run both together or choose one.

📌 Plex's built-in newsletter requires Plex Pass for the server owner and sends to users who have Plex accounts. The portal's newsletter works with just an email address and no Plex account required.
1

Open Plex Web Settings

In Plex Web, click the wrench icon (⚙️) in the top-right to open server settings. Make sure you're viewing your server's settings (not the Plex.tv account settings).

Plex Web App └── ⚙️ (Settings — top right) └── Your Server Name └── Extras ← scroll down in left sidebar
2

Enable Newsletter in Extras

In the Extras section, look for Newsletter. Toggle it on.

You can configure:

  • Frequency — Weekly or Monthly
  • Day and time — when to send it
  • Libraries to include — which Plex libraries appear in the digest
3

Who receives it

Plex's newsletter is automatically sent to all users you've shared your Plex library with (Plex home users). They receive it at their Plex account email address — no extra sign-up needed.

💡 Both systems together: Use Plex's newsletter for your Plex-account users, and the portal's newsletter for people who use the portal but don't have Plex accounts (e.g., family members who just use the portal to request content).
4

Send a test newsletter

In the same Extras → Newsletter section, there's a Send a Newsletter Now button. Click it to preview what users will receive before the scheduled send.

Step 5 — Understanding the Weekly Digest

The portal sends a weekly email digest every Friday at 9:00 AM server time. Here's exactly what it includes and how it works.

What's in the digest

🆕
New This Week — per library The 6 most-recently added items from each Plex library section (Movies, TV Shows, etc.). Each item shows its title, year, and a short synopsis. Poster thumbnails are loaded directly from your Plex server.
✅
Recently Fulfilled Requests Up to 10 recently-available items from Overseerr (if configured). Shows what was added as a result of user requests.

Library access per user

Currently the digest shows content from all Plex library sections the server has. Content is organised by library so it's easy to see what's new in Movies vs TV Shows vs other libraries.

📌 Future enhancement: Library-specific filtering per subscriber (so a subscriber who only uses the TV section won't see movie updates). This can be added by extending the subscription form with library preference checkboxes.

Sending manually

You don't have to wait until Friday. From the Admin Panel, click Send Weekly Digest Now to trigger it immediately. Useful for testing or for special announcements.

Scheduler details

Schedule: Every Friday at 09:00 AM (server/container timezone) Engine: APScheduler BackgroundScheduler Behaviour: Runs automatically — no cron job needed Manual: POST /newsletter/send-weekly (from Admin Panel)
Troubleshooting

❌ Test email is not arriving

  • Check the spam/junk folder — first emails often end up there
  • Verify your SMTP credentials are correct (re-test via Setup Wizard → email step)
  • For Gmail: make sure you're using an App Password, not your regular password
  • Check the container logs: docker logs plex-portal

❌ Overseerr webhook not receiving

  • Make sure the portal is accessible from where Overseerr is running (same Docker network, or correct IP/port)
  • Confirm the Webhook URL in Overseerr matches exactly: {{ webhook_url }}
  • If you have a webhook secret set, make sure the Authorization header in Overseerr is: Bearer <your-secret>
  • Check Overseerr's notification logs for errors

❌ User made a request but got no email

  • The user must be subscribed AND confirmed
  • The email or Plex username in the subscription must match what's in Overseerr
  • The subscription must have Request notifications enabled
  • SMTP must be configured

❌ Weekly digest has no content

  • Plex server URL and token must be set (in Setup Wizard or environment)
  • Check that Plex libraries exist and have content added in the last week
  • Check container logs for Plex content fetch failed errors
